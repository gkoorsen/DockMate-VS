# DockMate-VS 0.1.3

Release date: 2026-10-22

## Release baseline

This release packages the functionality on `master` at commit `32d3a93`, with
release-version and documentation updates. The registry, dedicated Vina/rDock
adapters, topology-aware pose export, engine-aware diagnostics, and their two
new test modules were added after the `v0.1.2` tag. They are included in v0.1.3;
they are not present in the archived v0.1.2 distribution.

## Highlights

- An explicit docking-engine registry shared by GUI, headless, and adaptive
  campaigns. Engine capabilities control preparation formats, applicable
  settings, binary discovery, site-definition provenance, and rescoring.
- Built-in Smina, Vina, and rDock adapters, with documented registration and
  per-engine options for additional engines. Registration is explicit; Python
  package entry-point auto-discovery is not implemented.
- `dockmate-vs doctor` lists registered engines and reports whether their
  required executables are available.
- `dockmate-vs export` writes a selected saved pose as SDF or receptor-ligand PDB.
  Prepared-ligand topology preserves bond orders while saved docking coordinates
  define the exported pose. Complex exports also include a ligand SDF.
- rDock protocol sweeps pass the condition-specific seed to the adapter. The
  rDock condition-version marker invalidates older cached conditions that used
  a fixed seed.
- README citation links distinguish the release-specific and concept DOIs.
  ESR1 case-study materials are described as journal supplementary material;
  repository copies remain available for convenience.

## Validation

- **309 tests passed** on a clean source snapshot of `32d3a93`, using Python
  3.9.15 on macOS, verified on 2026-10-22 with:

  ```bash
  python -m pytest dockmate_vs/tests -q -p no:cacheprovider
  ```

- Uncommitted working-tree changes are excluded from the release baseline.
- `test_engine_registry.py` covers registration, capabilities, binary-aware
  doctor output, a registered custom engine running and resuming a headless
  protocol-development campaign, adaptive dispatch, and built-in adapter
  command construction with mocked subprocess calls.
- `test_pose_export.py` checks prepared-topology and coordinate preservation,
  atom counts and canonical SMILES, a selectable ligand residue in complex PDB
  output, copied run folders, SDF inputs, and rejection of invalid pose indices,
  mismatched preparation, and unintended overwrites.
- The suite is not evidence of a fresh docking campaign with every external
  executable. Linux CI is configured for Python 3.9, 3.11, and 3.12; consult the
  release commit's checks for their results.

## Scope and compatibility

Existing built-in engine settings remain supported. The documented registry
extension path and pose-export command are described in
[`architecture.md`](../architecture.md) and [`md_handoff.md`](../md_handoff.md).
Pose export requires compatible prepared-ligand topology and verifies the atom
mapping instead of inferring chemistry solely from PDBQT.

Export automates the coordinate/topology handoff, not molecular-dynamics system
preparation. It does not supply force-field parameters, solvation, simulation
decks, or binding-free-energy setup. pH-aware ionization-state enumeration is
not implemented.

## Distribution and citation

Release assets comprise a source ZIP, Python source distribution, wheel,
SHA-256 checksums, and validation notes. Source archives include
`test_engine_registry.py` and `test_pose_export.py`; wheels include the runtime
modules but omit the test suite by design. External docking executables,
environments, cached run outputs, and separately licensed LigPlot+ are excluded.
